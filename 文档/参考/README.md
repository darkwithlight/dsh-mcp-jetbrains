## 为什么只留英文原文

**工具契约必须逐字读。** 参数名、必填项、`1-based` 行列、「只能分析项目内文件」这类规则，一旦经过翻译或 HTML→Markdown 转换就存在偏差风险；照着一份有偏差的副本去拼调用参数，代价比读英文高得多。

所以：**不留中文副本、不留转换产物**。需要中文解释时现场翻译具体那一段（问一句即可），不落盘——落盘的翻译版迟早会与上游分叉，而且没人会记得它是什么时候转的。

中文官网本身也存在，但它的页内「Markdown version of this page」链接是坏的：返回 HTTP 200 却是一个 HTML 404 页，拿不到纯净原文。英文站则正常。

## 能用什么、不能用什么

- **能用**：工具级约定——每个工具的参数、必填项、`1-based` 行列、只分析项目内文件这类硬规则。写代码或构造调用时按它来。
- **不能用**：传输层行为。官方文档**没有**写心跳、会话超时、重握手（整篇 30k 字符里「心跳」出现 0 次、「传输」出现 0 次）。这些属于实测结论，照我们的实测走，不要拿官方文档背书。

## 怎么刷新

版本升级（比如 IDEA 2027.1）或怀疑文档过时时重抓，文件名带版本号，别覆盖旧版：

```powershell
Invoke-WebRequest 'https://www.jetbrains.com/help/idea/2026.2/mcp-server.html.md' -OutFile 'mcp-server-2026.2.en.md'
```

注意只认 `.html.md` 这个形式：`mcp-server.md` 也存在，但那是另一份简报，不是逐字文档。
